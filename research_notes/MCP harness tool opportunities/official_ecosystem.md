# Official MCP ecosystem designs for harness tools

## What useful capabilities, metadata patterns, safety controls, discovery methods, and workflow primitives appear in authoritative MCP sources as of October 2026?

### Takeaway

The strongest design direction is a small, dynamically discoverable, permission-filtered tool surface with typed outputs, explicit durable handles, cacheable metadata, and bounded results. The July 2026 core protocol standardizes much of the substrate; vendors add useful conventions such as toolsets, read-only precedence, code-mode search/execute, workspace-scoped state, and result truncation. Sources were accessed 2026-10-07.

### Cited Findings

1. **Live discovery, statelessness, and explicit state are now core protocol patterns.** **[Standardized core]** MCP 2026-07-28 removes protocol sessions and `initialize`, requires request-scoped protocol/capability metadata, and adds mandatory `server/discover` for live identity, versions, and capabilities. Cross-call state must use server-minted handles passed as normal arguments. The tool specification recommends opaque, expiring handles, authorization checks on every use, and recoverable expiry errors. This is a direct model for transaction, browser, batch, or workflow handles in a harness. — [MCP 2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog); [stateful-tool guidance](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#stateful-tools)

2. **Progressive disclosure has three authoritative layers.** **[Standardized core]** Runtime `tools/list` is paginated, may change, may be filtered by per-request authorization, and should be deterministically ordered for client caching and model prompt-cache hits. List/read results now include `ttlMs` and `cacheScope`; opted-in changes use `subscriptions/listen` rather than an implicit session stream. **[Official extension]** Server Cards provide public, cacheable pre-connection identity, endpoints, headers/templates, and protocol versions, but deliberately omit tools and capabilities because those may vary by identity or deployment. **[Registry convention]** `server.json` carries reverse-DNS identity, package or remote location, execution arguments/environment variables, description, and capabilities; the Registry exposes a standard REST/OpenAPI interface while leaving curation and security enrichment to downstream aggregators. — [tool listing](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#listing-tools); [2026 caching/subscription changes](https://modelcontextprotocol.io/specification/2026-07-28/changelog); [SEP-2127 Server Cards](https://modelcontextprotocol.io/seps/2127-mcp-server-cards); [Registry overview](https://modelcontextprotocol.io/registry/about)

3. **Machine-usable results are first-class and can avoid flooding model context.** **[Standardized core]** Tools can define JSON Schema `outputSchema`; servers must make `structuredContent` conform and clients should validate it. Results can instead return resource links for deferred fetch, embedded resources, or content annotations for audience, priority, and modification time. Tool execution errors belong in `isError: true` results so models can self-correct; malformed requests remain JSON-RPC errors. This supports a harness split between compact summaries/IDs and opt-in detail retrieval. — [structured content and output schema](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#structured-content); [resource links](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#resource-links); [error handling](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#error-handling)

4. **Long workflows now have restart-safe protocol primitives.** **[Official extension]** MCP Tasks returns durable `taskId`, status, TTL, and suggested poll interval; `tasks/get` resumes after disconnect, `tasks/update` supplies requested human/model input, and `tasks/cancel` is cooperative. Statuses distinguish `working`, `input_required`, `completed`, `failed`, and `cancelled`; optional task notifications can replace polling. **[Standardized core]** Multi Round-Trip Requests let an ordinary call return `input_required` plus keyed requests and opaque `requestState`, then complete when the client retries with responses. Request-scoped progress uses a unique token and monotonically increasing values, with rate limiting recommended. — [MCP Tasks](https://modelcontextprotocol.io/specification/2026-07-28/basic/utilities/tasks); [MRTR change](https://modelcontextprotocol.io/specification/2026-07-28/changelog); [progress](https://modelcontextprotocol.io/specification/2026-07-28/basic/utilities/progress)

5. **Permissions should shape discovery, not only reject execution.** **[Standardized core]** HTTP authorization uses OAuth protected-resource and authorization-server discovery, audience-bound tokens, PKCE/resource indicators, least-privilege scope challenges, and step-up authorization. `tools/list` may expose only tools permitted by the presented authorization. Tool annotations remain untrusted hints; clients should display exposed tools, show invocations, and confirm sensitive operations. **[Vendor convention: GitHub]** GitHub filters tool visibility from classic PAT scopes and uses runtime scope challenges for remote OAuth. — [MCP authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization); [tool safety and authorization-sensitive listing](https://modelcontextprotocol.io/specification/2026-07-28/server/tools); [GitHub scope filtering](https://github.com/github/github-mcp-server/blob/main/docs/server-configuration.md#scope-filtering)

6. **GitHub demonstrates composable capability budgets and monotonic safety precedence.** **[Vendor-specific]** Its official server supports curated toolsets, individual allowlists, hard exclusions, read-only mode, and lockdown filtering. Exclusions override inclusions; read-only removes writes even if explicitly requested; operator-enabled lockdown cannot be relaxed by a request. Lockdown filters public-repository content from authors without push access to reduce prompt-injection exposure, but GitHub explicitly says it is not an authorization boundary. Toolsets may bundle tools, resources, and prompts. This is a strong harness model: broad semantic groups, fine-grained overrides, and server policy as an upper bound. — [GitHub server configuration](https://github.com/github/github-mcp-server/blob/main/docs/server-configuration.md); [GitHub MCP README](https://github.com/github/github-mcp-server)

7. **Cloudflare demonstrates server-side search/execute as both discovery and compression.** **[Vendor-specific]** Its official Code Mode server exposes `docs`, `search`, `execute`, and `whoami` rather than thousands of endpoint schemas. `search` runs code against the API specification; `execute` calls discovered endpoints. Cloudflare reports about 1,100 tool-schema tokens for Code Mode versus about 244,047 for 2,594 minimally described endpoint tools. Executions run in isolated Workers. Tool results are capped at about 6,000 tokens by default while preserving valid JSON and marking cuts; clients that enforce their own bounds can disable truncation. This is the clearest reusable non-CRUD primitive set found. — [Cloudflare MCP README](https://github.com/cloudflare/mcp/blob/main/README.md); [Code Mode SDK link](https://developers.cloudflare.com/agents/api-reference/codemode/)

8. **Playwright demonstrates semantic state, capability opt-in, and workspace isolation.** **[Vendor-specific]** It exposes generic browser workflow primitives through accessibility snapshots and exact element references rather than requiring vision. Optional capability groups cover vision, PDF, DevTools, network, storage, testing, and configuration. Persistent browser profiles are workspace-hashed; isolated sessions can start from explicit storage state. File access defaults to workspace roots, output files can be size-evicted, snapshots can be disabled, image responses can be omitted, and origin allow/block lists exist. Microsoft warns that Playwright MCP is not a security boundary and that origin filters do not cover redirects. — [Playwright MCP README](https://github.com/microsoft/playwright-mcp/blob/main/README.md)

9. **Sentry demonstrates workflow-focused tools, delegated intelligence, and deployment-aware exposure.** **[Vendor-specific]** Sentry states that its MCP is optimized for human-in-the-loop debugging workflows rather than full API coverage. Natural-language search tools translate user requests into Sentry query syntax through a configured embedded model; unavailable model-backed tools are omitted while other tools continue to work. Capability groups can be enabled or disabled, and self-hosted deployments omit unsupported Seer tools by default. Its remote transport separates MCP OAuth `Bearer` tokens from pass-through upstream `Sentry-Bearer` credentials. These patterns support graceful degradation and explicit separation between harness authentication and downstream credentials. — [Sentry Toolkit README](https://github.com/getsentry/toolkit/blob/main/README.md)

10. **Observability and routing metadata can remain outside model-visible payloads.** **[Standardized core]** MCP 2026-07-28 defines OpenTelemetry `traceparent`, `tracestate`, and `baggage` propagation through `_meta`, and moves log-level selection to per-request metadata. Streamable HTTP requests carry `Mcp-Method` and `Mcp-Name`; primitive tool parameters can opt into validated `Mcp-Param-*` headers through `x-mcp-header`, enabling proxy/WAF routing without body inspection. Sensitive values must not be exposed this way. This gives a harness correlation, policy-routing, and diagnostics channels without expanding natural-language results. — [2026 observability and header changes](https://modelcontextprotocol.io/specification/2026-07-28/changelog); [`x-mcp-header`](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#x-mcp-header)

### Inferences

- **Best opportunity for `mcptools`:** add a discovery facade that returns a small deterministic catalog, then fetches full schemas only for selected tools. Cache by server identity, authorization context, `ttlMs`, and protocol version; invalidate from list-change subscriptions. This combines the core listing/cache rules with GitHub-style toolsets. — [MCP tool listing](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#listing-tools); [GitHub configuration](https://github.com/github/github-mcp-server/blob/main/docs/server-configuration.md)
- **Use policy as data:** normalize read/write/destructive/open-world hints, but never trust annotations alone. Apply local deny/read-only rules after server discovery, with deny taking precedence over allow, and require confirmation at the final call boundary. — [MCP tool safety](https://modelcontextprotocol.io/specification/2026-07-28/server/tools); [GitHub precedence rules](https://github.com/github/github-mcp-server/blob/main/docs/server-configuration.md#how-configuration-works)
- **Offer two execution shapes:** typed direct calls for narrow, high-assurance operations; sandboxed search/execute for very large APIs or multi-step data reduction. Bound CPU, network destinations, output bytes/tokens, and mutation retries; Cloudflare notes that broad uncapped results can reach megabytes. — [Cloudflare MCP README](https://github.com/cloudflare/mcp/blob/main/README.md)
- **Make handles the common workflow primitive:** represent tasks, browser contexts, transactions, and large result sets as opaque, authorized, expiring IDs. Store enough state to resume after reconnect, and return compact status plus deferred resource links. — [stateful tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#stateful-tools); [MCP Tasks](https://modelcontextprotocol.io/specification/2026-07-28/basic/utilities/tasks)
- **Treat compression as semantic, not textual:** prefer projection/filter/aggregation in a sandbox, structured output schemas, stable truncation metadata, and resource links over arbitrary string clipping. — [Cloudflare result truncation and Code Mode](https://github.com/cloudflare/mcp/blob/main/README.md); [MCP structured results](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#structured-content)

### Gaps

- No standardized core batch-call method was found. Tasks support batch workloads, but Code Mode composition is a vendor convention rather than MCP batching.
- No standardized trusted permission taxonomy was found beyond OAuth scopes and untrusted tool annotations; hosts still need local policy.
- Linear, Atlassian, and Neon were not verified within the 20-call research budget. No claim is made about their October 2026 tool surfaces.
- The Registry remains preview and explicitly delegates scanning/curation to package registries and downstream aggregators; namespace verification is not code safety. — [Registry trust model](https://modelcontextprotocol.io/registry/about#trust-and-security)
- Roots, Sampling, Logging, HTTP+SSE, and OAuth Dynamic Client Registration are deprecated in the 2026-07-28 revision. New harness work should use explicit parameters/resource URIs, direct model integration, stderr/OpenTelemetry, Streamable HTTP, and Client ID Metadata Documents. — [MCP 2026-07-28 deprecations](https://modelcontextprotocol.io/specification/2026-07-28/changelog#deprecated)
